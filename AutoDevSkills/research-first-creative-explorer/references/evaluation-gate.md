# Evaluation gate (Phase F)

Evaluate **only after** the idea space is fully explored (Phases A–E complete and
the novelty audit passed). These criteria decide *what is worth validating or
building* — they must never throttle divergence.

## Evaluation order

Score standout concepts in this order; a fatal problem early can stop the rest:

1. **User Value** — is there a real, specific person with a real need/desire, and
   is the value compelling versus their current alternative? No value → stop.
2. **Data Reliability** — does the concept depend on data/inputs that are
   available, legal, accurate, and durable? Flag data risks explicitly.
3. **Distribution** — is there a credible path to reach the first 10, then 100,
   then 1000 users? A great product with no distribution path is parked.
4. **Extensible Architecture** — *last*: can it grow beyond v1 without a rewrite?
   Only relevant once value/data/distribution hold.

Do not let these bury a strange-but-strong idea during Phases D–E; apply them here.

## Per-concept dossier (for each standout concept)

- **Specific user** — who exactly (narrow beats "everyone").
- **Problem or desire** — the felt need.
- **Moment of use** — when/where it fires.
- **Current alternative** — what they do today (incl. doing nothing).
- **Minimum compelling value** — the smallest version that's still worth it.
- **Existing evidence** — cited; label Fact/Inference/Speculation.
- **Biggest assumption** — the one that, if wrong, sinks it.
- **Data risk** — availability / legality / accuracy / decay.
- **Distribution path** — concrete route to 10 → 100 → 1000 users.
- **Why it could fail** — the strongest honest counterargument.
- **Cheapest experiment** — the fastest, smallest test of the biggest assumption
  (often no code: a landing page, 5 interviews, a fake door, a manual concierge
  run, a physical prototype).
- **Signal to continue** — what result would justify going further.
- **Kill criteria** — what result means stop.

## Verdicts

End each standout concept with exactly one verdict:

- **BUILD NOW** — value, data, and distribution are credible; low-risk to start.
- **VALIDATE FIRST** — promising but rests on an untested key assumption.
- **REDUCE SCOPE** — strong core buried in too-big a v1; cut it down.
- **DATA FIRST** — hinges on data that must be secured/verified before building.
- **DISTRIBUTION FIRST** — good product, unproven path to users; solve reach first.
- **PARK** — interesting but not now (wrong timing, weak pull, better options).
- **DO NOT BUILD** — fails a core gate; record why so it isn't re-proposed.

Only propose specific technology/architecture **after** a concept clears these
gates. Technology choice is an implementation detail of a validated concept, not
the starting point.
